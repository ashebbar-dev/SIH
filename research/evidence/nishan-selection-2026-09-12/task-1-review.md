### Important

**I1 — Pre-existing package-type dispatch can evade the newly advertised all-PDF-source rule.** A party able to edit the encrypted package before its first authorized issuance can change only `source.media_type` from `application/pdf` to `image`, leaving `filename` ending in `.pdf`. The document's AES-GCM associated data contains only the document ID; key wrapping binds document ID and recipient, not this metadata (`prototypes/nishan_pq/nishan/core.py:116`, `prototypes/nishan_pq/nishan/core.py:125`). No attacker key access or cryptographic forgery is needed; a legitimate recipient still invokes normal authorized decryption.

The release branch trusts that unauthenticated field (`prototypes/nishan_pq/nishan/core.py:255`), and the generic branch signs `nishan-spread-spectrum-session/v1` (`prototypes/nishan_pq/nishan/core.py:352`). Its unchanged embedder accepts actual PDF content and writes a rasterized marked PDF when the retained filename ends in `.pdf` (`prototypes/nishan_pq/nishan/watermark.py:112`, `prototypes/nishan_pq/nishan/watermark.py:125`). A healthy pinned witness authenticates this generic receipt normally. With no earlier Tardos issuance for the document, trace dispatches solely on the signed fingerprint scheme and reaches generic single-channel scoring, where above-threshold rows populate `attribution`; no PDF corroboration check is reached (`prototypes/nishan_pq/nishan/core.py:1015`, `prototypes/nishan_pq/nishan/core.py:1035`, `prototypes/nishan_pq/nishan/core.py:1080`). This describes the established control-flow bypass; no empirical default-threshold success rate was measured in this review.

**Provenance and scope:** Read-only comparison with the retained `before.tar.gz` confirms that the unauthenticated dispatch and generic PDF acceptance existed before Task 1. The specification's precise security bullet says **Tardos** PDF-source tracing, and README line 97 uses that narrower scope; those narrow statements are implemented. However, the task's conservative PDF-source outcome and new README lines 31, 223 and 277 promise corroboration for **every/all PDF-source** trace. Preserving genuine generic-image screening does not require treating an actual PDF as an image because its package label was edited. This is an Important missing guard/assurance-boundary disclosure in the new task outcome, not evidence that witness locking or signatures are broken.

**Resolution:** Classify authenticated plaintext with the existing content parser before selecting the release path, rejecting an inconsistent package label or routing actual PDFs through the existing Tardos path. At trace time, actual PDF references with only legacy generic receipts must abstain from PDF attribution or explicitly expose the legacy exception. Preserve genuine image screening. Add a focused regression that changes only an otherwise valid PDF package's media-type field before first issuance, uses ordinary strict release/trace, and proves the altered label cannot yield generic PDF attribution. If the controller intentionally limits Task 1 to already-Tardos records, the alternative is to make that exception explicit and consistent in every claim and report it as unresolved future hardening; blanket PDF-source claims should not ship unchanged.
